# Архитектура

## Что это за сервис

Виртуальная визитка сотрудника: страница вида `domain.com/employee/{slug}` и
скачиваемая PNG-карточка на её основе. Компания — единица изоляции данных,
попасть в неё можно только по приглашению администратора.

## Один сервис, а не микросервисы

В названии исходного ТЗ стоит «микросервис», но по функционалу это **один
процесс**. Дробить его не на что: единственная граница, которая напрашивалась, —
генерация картинки, и та исчезла, когда рендер уехал с headless-браузера в Go.
Браузер потребовал бы отдельного деплоя из-за сотен мегабайт памяти и
принципиально другого профиля нагрузки; отрисовка кодом стоит миллисекунды
и живёт в том же процессе.

Почтовый рассыльщик тоже работает внутри `cmd/api`. Очередь лежит в Postgres,
поэтому вынести его в отдельную команду можно будет без единой правки в коде —
когда объём писем это оправдает.

## Слои

```
      HTTP (ogen, сгенерирован из OpenAPI)
                 │
   internal/handler/http   — транспорт: разбор уже сделан, тут только перевод
                 │            доменных типов в контрактные и обратно
   internal/service/*      — сценарии: права, доменные правила, транзакции
                 │
   internal/domain         — сущности и правила, не зависящие ни от чего
                 │
   internal/repository/postgres — SQL, перевод ошибок драйвера в доменные
```

Правило зависимостей одностороннее: домен не знает ни про HTTP, ни про SQL.
Сгенерированные ogen-структуры не проходят глубже пакета `handler/http` —
иначе смена версии OpenAPI переписывала бы домен.

**Интерфейсы объявляет потребитель.** `service/auth` описывает у себя
`UserRepo`, а `repository/postgres` про этот интерфейс не знает. Так репозиторий
не превращается в узел, от которого зависит всё, а моки в тестах остаются
локальными.

## Пакеты

| Пакет | Зачем |
|---|---|
| `cmd/api` | сборка зависимостей, два HTTP-сервера, воркер, сигналы |
| `cmd/migrator` | миграции отдельным бинарём — это шаг релиза, а не старта |
| `internal/config` | единственное место, которому позволено читать окружение |
| `internal/domain` | сущности, доменные ошибки, правила (слаги, теги, статусы) |
| `internal/service/auth` | регистрация, вход, ротация токенов, сессии |
| `internal/service/company` | тенант, справочники, состав |
| `internal/service/invitation` | приглашения и их приём |
| `internal/service/profile` | визитка, санитизация, публикация |
| `internal/service/card` | сборка карточки и её кэш |
| `internal/render` | сама отрисовка: PNG и SVG из одной раскладки |
| `internal/repository/postgres` | SQL и перевод SQLSTATE в доменные ошибки |
| `internal/storage` | `BlobStore` + реализация на локальном диске |
| `internal/email` | шаблоны писем и отправка по SMTP |
| `internal/worker` | разбор очереди исходящих писем |
| `internal/handler/http` | реализация сгенерированного интерфейса |
| `internal/handler/files` | раздача загруженных файлов (вне спеки) |
| `internal/handler/middleware` | request-id, логи, паники, условные запросы |
| `internal/platform/*` | логгер, пул Postgres, HTTP-сервер, пробы и метрики |

## Два HTTP-слушателя

- **`:8080`** — публичный API (`/api/v1/**`) и раздача файлов (`/files/**`).
- **`:9090`** — служебный: `/healthz`, `/readyz`, `/metrics`.

Разделены намеренно: пробы и метрики не должны быть доступны снаружи вместе
с API и не должны падать вместе с ним под нагрузкой. В OpenAPI-спеке их нет —
это контракт со средой исполнения, а не с фронтом.

`/healthz` **не ходит в базу**. Если добавить туда проверку зависимостей,
кратковременная недоступность Postgres заставит Kubernetes перезапустить
совершенно здоровые поды и сделает хуже. Проверка базы — в `/readyz`,
где под просто выводится из балансировки до восстановления.

## Путь запроса

```
запрос
  → RequestID        присваивает идентификатор, возвращает его в заголовке
  → Recover          паника в обработчике не роняет процесс
  → AccessLog        строка в stdout; путь приёма приглашения маскируется
  → ClientInfo       IP и User-Agent для списка сессий
  → ConditionalGet   If-None-Match → 304, если ETag совпал
  → mux              /files/** — статика, остальное — сгенерированный роутер
  → SecurityHandler  проверка подписи access-токена, без обращения к базе
  → обработчик       → сценарий → репозиторий
```

Порядок не случаен: `RequestID` первым, чтобы идентификатор был доступен и логу,
и обработчику паники; `ConditionalGet` ниже логирования, чтобы в журнал попадал
реальный код ответа, включая 304.

## Ошибки

Домен возвращает свои ошибки (`ErrNotFound`, `ErrConflict`, `ErrLastAdmin`, …),
репозиторий переводит в них SQLSTATE, транспорт — отображает в коды ответов.
Ни один слой не выдумывает собственного словаря.

Единая точка отображения — `internal/handler/http/errors.go`. Наружу уходит
только машиночитаемый `code`: текст ошибки может содержать имена таблиц,
фрагменты запросов и значения полей, поэтому подробности остаются в логе,
а связь между ними — по `requestId`.

Есть тонкость: **отказы аутентификации ogen направляет не в `ErrorHandler`,
а в метод `NewError` обработчика**. Оба пути ведут в общий `mapError`, иначе
запрос без токена отвечал бы пятисоткой.

## Отрисовка карточки

`internal/render` рисует **PNG и SVG из одного набора команд** —
`tdewolff/canvas` умеет оба вывода, поэтому форматам нечем разойтись.

- Шрифты — семейство Go, вкомпилированы модулем. Не файлы на диске: иначе
  в образе появляется путь, за которым надо следить, и карточка ломается
  не при сборке, а квадратами вместо букв при первом запросе.
- Круглый аватар — маска, вшитая в пиксели (у canvas клип только
  прямоугольный). Фон непрозрачный: на прозрачных углах PNG получил бы
  чёрные квадраты вокруг лица.
- В SVG шрифт вкомпилируется **подмножеством** — 16 КБ вместо 400.
- Отрисовка детерминирована, поэтому кэш строится на хэше, а макет
  защищён эталонными изображениями в тестах.

Кэш: имя файла — `hash(данные профиля + версия рендерера)`. Найденный файл
заведомо актуален, устареть под тем же именем он не может. Правка макета
сопровождается подъёмом `render.Version` и разом обесценивает все старые
картинки — без ручной чистки хранилища.

## Хранилище файлов

Всё лежит за интерфейсом `storage.BlobStore`; сейчас реализация одна —
локальный диск. Это **осознанный долг**: процесс перестаёт быть stateless,
и вторую реплику с ним поднимать нельзя, половина аватарок окажется не на том
поде. Смысл интерфейса в том, чтобы переезд на S3 стоил одного нового файла
и переменной окружения.

Отсюда правило: **в базе хранится ключ, никогда не URL**. Ключ не зависит
от того, где файлы лежат сегодня.
