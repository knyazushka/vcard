# Эксплуатация

## Двенадцать факторов

Не декларация, а список конкретных следствий в коде.

| | Как сделано |
|---|---|
| **I. Кодовая база** | один репозиторий, два бинаря из одного модуля — версия схемы и версия кода не расходятся |
| **II. Зависимости** | `go.mod`; ogen, goose и golangci-lint закреплены `tool`-директивами |
| **III. Конфигурация** | только окружение, `internal/config` — единственное место с доступом к нему |
| **IV. Сторонние сервисы** | Postgres, SMTP, хранилище файлов — за интерфейсами, адреса из окружения |
| **V. Сборка/релиз/запуск** | миграции отдельным бинарём, **не при старте приложения** |
| **VI. Процессы** | сессии не в памяти; кэш карточек в хранилище. Долг — локальный диск, см. ниже |
| **VII. Привязка портов** | `net/http` слушает сам, никакого веб-сервера внутри контейнера |
| **VIII. Масштабирование** | процесс без состояния — кроме локального хранилища |
| **IX. Утилизируемость** | корректная остановка по SIGTERM с таймаутом |
| **X. Паритет сред** | в разработке те же Postgres и SMTP, что в проде; версии образов закреплены |
| **XI. Логи** | `log/slog` в stdout, JSON в проде, текст в разработке. Ни файлов, ни ротации |
| **XII. Управляющие задачи** | миграции — подкоманды того же модуля, не отдельные скрипты |

## Порты

| Порт | Что |
|---|---|
| `8080` | API (`/api/v1/**`) и файлы (`/files/**`) |
| `9090` | `/healthz`, `/readyz`, `/metrics` — наружу не публиковать |

## Пробы

- **`/healthz`** — процесс жив. **В базу не ходит намеренно:** проверка
  зависимостей здесь означала бы, что кратковременная недоступность Postgres
  заставляет Kubernetes перезапускать совершенно здоровые поды.
- **`/readyz`** — можем обслуживать прямо сейчас, с проверкой базы. Под просто
  выводится из балансировки до восстановления.

## Порядок выкатки

```
1. migrator up      (init-контейнер или отдельный job)
2. api              (после успешной миграции)
```

Миграции обязаны быть совместимы с **предыдущей** версией кода: во время
выкатки старые и новые поды работают одновременно.

## Остановка

По SIGINT/SIGTERM процесс перестаёт принимать новые соединения, даёт доработать
текущим и по истечении `HTTP_SHUTDOWN_TIMEOUT` (15 с) рвёт принудительно.
Останавливаются оба сервера и почтовый воркер.

Письмо, взятое в работу и не отправленное, вернётся в очередь: аренда
в `email_outbox` истекает, и следующий тик заберёт его снова.

## Масштабирование: одна реплика

Пока `STORAGE_DRIVER=local`, **реплика должна быть одна**. Аватарки и карточки
лежат на диске пода; со второй репликой половина файлов окажется не там.

В манифесте — `replicas: 1` и PVC. Это осознанный долг первого этапа,
изолированный интерфейсом `storage.BlobStore`: переезд на S3 — новый адаптер
и переменная окружения, без миграции данных.

Почтовый воркер к этому готов заранее: `FOR UPDATE SKIP LOCKED` позволяет
нескольким процессам разбирать очередь, не отправляя письмо дважды.

## Что смотреть при инцидентах

**Метрики** — стандартные Go-метрики на `:9090/metrics`. Прикладных пока нет;
первыми стоит добавить время отрисовки карточки и глубину очереди писем.

**Логи** — JSON в stdout. Ключевые поля: `request_id` (он же в заголовке
`X-Request-Id` ответа — по нему клиентская жалоба связывается с записью),
`status`, `duration_ms`.

Уровень ERROR — только настоящие пятисотки. 501 «операция не реализована»
туда не попадает намеренно: иначе уровень стал бы нечитаемым.

Отдельно стоит следить за строкой `refresh token reuse detected` — это признак
кражи токена, а не рутина.

**Очередь писем**:

```sql
select status, count(*), max(attempts) from email_outbox group by status;
```

Письма после шести неудачных попыток переходят в `FAILED` и остаются
в таблице как след для разбирательства.

## Долги, влияющие на эксплуатацию

1. **Rate limit не реализован** — 429 в спеке описан, кода нет. До продакшена
   закрыть либо в приложении, либо на ingress.
2. **Одна реплика** — следствие локального хранилища.
3. **Ротации ключа JWT нет** — смена секрета разлогинит всех.
4. **Протухшие сессии не чистятся** — `sessions` растёт с каждым входом.
   Метод `DeleteExpired` есть, воркера нет.
5. **Старые карточки не удаляются.** Правка профиля порождает новый файл,
   прежний остаётся. Место дешёвое, но уборщик когда-нибудь понадобится.
