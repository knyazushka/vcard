# Разработка

## Что нужно

- Go 1.26+
- Docker (Postgres и Mailpit); для прод-стенда — Docker Compose 2.30+
- Node — только для линтера и бандлера спеки, запускается через `npx`
- Bash — для сценариев прод-стенда; под Windows подходит Git Bash

Инструменты кодогенерации (`ogen`, `goose`, `golangci-lint`) закреплены
`tool`-директивами в `go.mod` и ставятся сами. Отдельно устанавливать
и держать в PATH ничего не нужно — иначе «у меня генерится, у тебя нет»
становится вопросом времени.

## Запуск

```bash
make db-up                    # Postgres на 5433, Mailpit на 1025/8025
make migrate-up
cp .env.example .env          # при необходимости поправить
go run ./cmd/api
```

Сервис поднимет два слушателя: `:8080` — API и файлы, `:9090` — пробы
и метрики.

Письма никуда не уходят: их ловит Mailpit, смотреть на <http://localhost:8025>.

Файлы в разработке лежат на диске (`STORAGE_DRIVER=local`, `./var/blobs`),
лимиты частоты включены так же, как в проде, CORS разрешает фронту
на `http://localhost:3000`.

Проверить то, что зависит от окружения прода — Caddy, S3, выкатку,
мониторинг, — можно на [локальном прод-стенде](operations.md#локальный-прод-стенд):
`make stand-up`.

## Команды

| Команда | Что делает |
|---|---|
| `make api-lint` | проверить спеку |
| `make api-bundle` | сшить многофайловую спеку в один документ |
| `make api-gen` | линт → бандл → генерация серверного кода |
| `make api-check` | для CI: падает, если код разошёлся со спекой |
| `make build` / `make test` | сборка и тесты |
| `make lint` / `make lint-fix` | golangci-lint |
| `make db-up` / `make db-down` | контейнеры |
| `make migrate-up` / `migrate-down` / `migrate-status` | миграции |
| `make migrate-verify` | вверх → полный откат → вверх |
| `make stand-up` / `stand-smoke` / `stand-down` | локальный прод-стенд: поднять, проверить, удалить |

## Конфигурация

Только окружение — никаких `config.yaml` с дефолтами, различающимися между
стендами. Полный список с комментариями — в `.env.example` и
`internal/config/config.go`.

Обязательны и не имеют значений по умолчанию:

| Переменная | Почему без дефолта |
|---|---|
| `DATABASE_URL` | — |
| `JWT_SECRET` | дефолтный секрет — это отсутствие подписи, просто незаметное; минимум 32 байта |
| `PUBLIC_APP_URL` | из него собираются ссылки в письмах |

Конфиг проверяется на старте: упасть с внятным сообщением дешевле, чем
обнаружить кривой адрес в момент отправки письма. Так же проверяются
`CORS_ALLOWED_ORIGINS` (origin со слэшем в конце молча не совпал бы ни с одним
запросом) и настройки S3 при `STORAGE_DRIVER=s3`.

Новая переменная окружения — это ещё и строка в job `deploy` в
`.github/workflows/release.yml`: в прод уходит только явно перечисленное
(см. [эксплуатацию](operations.md#конфигурация)).

## Тесты

```bash
go test ./...
```

Быстрые и без базы — проверяют то, что определяется только кодом:
хэширование паролей и разбор токенов, ротацию сессий и обнаружение кражи
refresh, нормализацию слагов, санитизацию HTML, сборку писем, условные
запросы, отрисовку карточки. И то, что появилось с подготовкой к проду:

- **CORS** — в том числе что чужой origin, `null` и origin со слэшем
  разрешений не получают;
- **ограничитель** — с подменёнными часами, без `sleep`: всплеск, пополнение,
  `Retry-After`, уборка корзин, IPv6 по `/64`;
- **имена операций** — строгие операции прогоняются настоящими путями через
  роутер ogen: опечатка в имени молча выключила бы строгий лимит;
- **метрики** — что 500 от паники и 429 попадают в счётчики, коллекторы
  пула и очереди регистрируются и не роняют сбор при недоступной базе;
- **конфиг** и **S3-адаптер** — проверки на старте, очистка ключей.

### Эталонные изображения

`internal/render/testdata/*.png` сравниваются побайтово. Это возможно потому,
что отрисовка детерминирована — отдельный тест это и проверяет.

Если макет менялся намеренно:

```bash
go test ./internal/render/ -update
```

и **поднять `render.Version`** — она входит в хэш имени файла карточки,
иначе у части сотрудников останется старый дизайн под тем же адресом.
Обновлённые эталоны надо посмотреть глазами: тест сравнивает байты,
«правильно» решает человек.

### Чего в тестах нет

Интеграционных тестов репозиториев с базой пока нет. Частично их закрывают
две вещи: CI прогоняет миграции вверх, вниз и снова вверх на настоящем
Postgres, а `make stand-smoke` проходит основные сценарии через настоящий
HTTP, Postgres, S3 и SMTP. Когда тесты появятся — только `testcontainers`
с настоящим Postgres: половина схемы (`citext`, генерируемые столбцы,
частичные уникальные индексы, constraint-триггеры) в SQLite не существует,
и зелёные тесты на подменённом диалекте ничего не значат.

## CI

`.github/workflows/ci.yml` — на каждый PR (кроме правок только в `docs/`
и `*.md`), три параллельных job:

| Job | Что |
|---|---|
| `lint` | `make lint` |
| `test` | `go test -race ./...` и `make migrate-verify` на Postgres 18 в сервис-контейнере |
| `contract` | `make api-check` — код не разошёлся со спекой |

Те же проверки — первый шаг выкатки при push в `main`, см.
[эксплуатацию](operations.md#выкатка).

## Окружение

Postgres в compose висит на **5433**, а не 5432: на стандартном порту обычно
уже слушает локально установленный сервер, и клиент молча уходит не туда.
Версия образа закреплена до минорной — плавающий тег однажды подтянул образ
со сменившейся точкой монтирования, и окружение перестало подниматься.

Mailpit — не заглушка, а настоящий SMTP-сервер: письма отправляются
по-настоящему, просто оседают локально. Подменять его моком значило бы
не проверять почтовый путь вовсе.

## Стиль

- Комментарии объясняют **почему**, а не что делает строка. «Что» видно
  из кода, «почему» — только из головы автора.
- Интерфейсы объявляет потребитель, а не реализация.
- Ошибки драйвера переводятся в доменные в репозитории; выше по стеку
  никто не знает про SQLSTATE.
- `nolint` — только с объяснением причины: без него это способ спрятать
  проблему.

## Полезное при отладке

```bash
# что в очереди писем
docker compose exec postgres psql -U vcard -d vcard \
  -c "select kind, to_email, status, attempts, last_error from email_outbox;"

# состояние сессий
docker compose exec postgres psql -U vcard -d vcard \
  -c "select user_id, used_at is not null as rotated, revoked_at from sessions;"

# отдать карточку в файл
curl -s http://localhost:8080/api/v1/public/employee/{slug}/card.png -o card.png
```
