# Контракт и кодогенерация

Спека — **источник истины**. Сервер генерируется из неё, клиент фронта тоже.
Рассинхрон ловится компилятором, а не тестировщиком.

## Где что лежит

```
api/openapi/
├── openapi.yaml            корень: info, servers, security по умолчанию, пути
├── openapi.bundled.yaml    сшитый файл — вход для ogen и для фронта
├── redocly.yaml            правила линтера
├── components/             схемы, переиспользуемые ответы и параметры
│   ├── common.yaml         security, ошибки, пагинация, базовые типы
│   ├── auth.yaml   company.yaml   invitation.yaml   profile.yaml
└── paths/                  операции
    ├── public.yaml  auth.yaml  companies.yaml  invitations.yaml  profiles.yaml

internal/gen/openapi/       сгенерированный код — руками не трогаем
```

39 операций: публичные 3, auth 6, компании 15, приглашения 6, профили 9.

## Как менять контракт

```bash
make api-gen     # линт → бандл → генерация
```

Порядок обязателен. **ogen не ходит по внешним `$ref`**, поэтому многофайловая
спека сначала сшивается `redocly bundle` в один документ; он же отдаётся фронту
для `openapi-typescript` — одним файлом вместо дерева.

После генерации реализуйте новые методы в `internal/handler/http`. Пока метод
не написан, встроенный `openapi.UnimplementedHandler` отвечает 501 — сервис
поднимается и маршрутизируется целиком.

> Встраивание `UnimplementedHandler` нужно убрать, когда будут реализованы все
> операции: с ним пропущенный метод перестаёт быть ошибкой компиляции,
> а это главное свойство contract-first.

В CI:

```bash
make api-check   # падает, если сгенерированное разошлось со спекой
```

## Соглашения контракта

### Версия — OpenAPI 3.0.3

Не 3.1: у ogen и генераторов TS её поддержка неровная. Отсюда особенность —
**`nullable` работает только рядом с `type`**, поэтому связка `$ref` + `nullable`
молча не действует. Для этого заведены явные двойники: `UUIDNullable`,
`URLNullable`, `TimestampNullable`, `SlugNullable`.

Ещё: **соседи у `$ref` игнорируются**. Описание поля рядом со ссылкой
не попадёт в документацию — если нужен свой комментарий, поле описывается
целиком.

### `Error.code` — строка, а не enum

Закрытый список сделал бы добавление нового кода ломающим изменением для уже
выкаченных клиентов: генераторы падают на неизвестном значении enum. Известные
коды перечислены в описании схемы `Error`; фронт ветвится по ним, сервер волен
добавлять.

Формат ошибки одинаков для всех путей — и прикладных, и транспортных.

### Публичные схемы отдельные

`ProfilePublic` и `CompanyPublic` — самостоятельные типы, а не `Profile`
с занулением полей. Следующее поле, добавленное в приватную схему, физически
не может утечь наружу.

### 404 вместо 403 для чужого ресурса

Отсутствие ресурса и отсутствие прав на него дают одинаковый ответ. Иначе
по кодам ответов перебираются чужие идентификаторы.

### `default`-ответ у каждой операции

Ogen генерирует хук `NewError` только когда `default` объявлен везде. Без него
паника или незамапленная ошибка уходят клиенту голым 500 без тела, и фронт
не отличает её от сетевого сбоя.

### Правила, которых нет в схеме

Схема стережёт форму, домен — правила. В схеме намеренно **не** выражены:

- должность задаётся ссылкой или текстом, но не обоими сразу;
- сумма справочных и своих тегов не больше трёх;
- публикация требует имени и ровно трёх тегов.

Они описаны в `description` соответствующих схем и проверяются в сервисах.

### Слаг: два разных правила

`SlugLookup` (path-параметр) допускает любой регистр — ссылку набирают руками
и копируют из письма. `Slug` (запись и ответы) — только нижний.

## Кэширование

Публичная страница и карточка отдают `ETag` и короткий `Cache-Control`.
Условные запросы обрабатывает middleware `ConditionalGet`: ogen сам на
`If-None-Match` не реагирует, и без него заголовок был бы бесполезен.

Вечный кэш — только у адресов с хэшем в имени файла (`cardImageUrl`,
`/files/**`): по ним содержимое уже не изменится.

## Для фронта

Фронт (`vc.knyazushka.ru`) и API (`vc-api.knyazushka.ru`) — разные origin,
поэтому запросы из браузера идут через CORS. Разрешены только origin
из `CORS_ALLOWED_ORIGINS`; в разработке — `http://localhost:3000`.

- **Access-токен** — в памяти JS, заголовком `Authorization: Bearer`.
  Не в `localStorage`, см. [безопасность](security.md).
- **Refresh** живёт в httpOnly-cookie и привязан к хосту API. Запросы
  к `/auth/**` (`refresh`, `logout`, вход и регистрация, где cookie
  выставляется) — с `credentials: 'include'`, иначе браузер её не отправит
  и не сохранит. Остальным запросам cookie не нужна.
- **429** может прийти от любой операции: общий лимит — на всё API,
  а в спеке ответ описан только у тех, где лимит строгий (для остальных это
  `default`). Тело — обычный `Error` с `code: rate_limited`, заголовок
  `Retry-After` — через сколько секунд повторять.
- **`X-Request-Id`** странице доступен — его стоит показывать в сообщении
  об ошибке: по нему запрос находится в логах.
- **Ссылки на файлы** приходят в ответах готовыми (`/files/...` на хосте
  API); собирать их на фронте не нужно.
- **SSR** обращается к API с адреса сервера фронта, и для ограничителя
  все посетители публичных страниц станут одним клиентом. Серверу фронта
  нужно ходить в API по внутренней сети с `X-Forwarded-For` посетителя —
  подробности в [безопасности](security.md#ограничение-частоты).

## Файлы вне спеки

`/files/**` (раздача загруженного), `/healthz`, `/readyz`, `/metrics`
в OpenAPI не описаны. Это доставка статики и контракт со средой исполнения,
а не операции API.
